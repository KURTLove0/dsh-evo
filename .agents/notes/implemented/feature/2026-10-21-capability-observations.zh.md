# Agent Note：能力观察与临时 MCP 检测

Status: implemented

[English](2026-10-21-capability-observations.md) | 中文

## 问题

运行时已注册、模型目录可读、凭证已配置与任务成功是不同的观察结果。将它们合并为一个健康标记，会让用户获得证据不足的信心。连接检测会启动进程或访问已保存的地址；响应丢失后重复提交可能导致重复执行。

## 决策

[能力检查](../../../../packages/business/capability-health/README.zh.md)以服务定义、原生提供方和生成的 Remote 消费方组合拥有配置观察及临时 MCP 检测。[浏览器页面](../../../../packages/client/ui-capability-health/README.zh.md)打开既有修复入口，不直接编辑配置。页面复用赛博主题，仅在插槽存储中声明视图草稿；[HealthManager](../../../../packages/client/runtime/README.zh.md)在页面重新挂载时保留报告及已提交标识。

配置检查保留各来源的独立结果，使用封闭诊断键，仅展示凭证存在性及来源，不解析密钥，也不宣称认证有效。所选检查捕获执行者版本及工作区，并将任务依赖委托给已有预检。前置条件不可用时，依赖它的检查仍为未验证。目录读取仅获取元数据；检查不创建执行会话或模型输入。

[MCP 辅助函数](../../../../packages/mcp/mcp-client/README.zh.md)通过已有 SDK 传输进行初始化及 ping，不发现、注册或执行工具，也不启用重连监督。每次显式检测捕获已保存的服务选择，并独立拥有标识、取消信号、时限及清理观察。保留的标识使相同准入请求可重放；字段冲突则拒绝。响应丢失后仅读取该标识，绝不自动重新提交。宿主重启会使旧标识变为未知。

清理在 SDK 关闭流程完成后观察实际传输关闭。清理失败会阻止新检测，直到宿主服务重新加载，以免重复启动进程累积未解决的资源泄漏。准入、保留数量、报告大小及并发都有上限，且不会驱逐可恢复的标识。卸载会取消并等待所属检测及读取。通知直接携带权威标识；监听器错误不能使已准入工作表现为拒绝，同步不变量失败仍然可见。

## 影响

配置变更会使持有的报告过期，不自动运行检查。显式来源读取可访问已有目录提供方，显式 stdio 检测会在所选工作区执行已保存命令。结果包含观察时间，分别记录连接及清理状态。宿主记录缺失时保留浏览器最后已知证据。浏览器重新加载会丢失该应用的待确认标识集合；检测记录是临时宿主状态，不是审计日志。

[MCP 桥接](2026-07-07-mcp-client-plugin.zh.md)和[重连决策](2026-08-06-mcp-client-auto-reconnect.zh.md)继续约束执行过程中的工具连接。[工作中心](2026-10-20-work-center-intake-and-review.zh.md)继续负责任务提交与验收。配置观察不替代工具监督或任务执行。[产品提案](../../proposed/feature/2026-10-20-outcome-oriented-workbench-product.zh.md)继续保留后续诊断及其他未实现能力。

## 验证

单元及真实 SDK 进程用例覆盖安全错误结果、取消、超时、SDK 终止升级、实际退出、清理失败、容量、版本检查、来源局部失败及观察者生命周期。运行时与组件用例覆盖过期读取、延迟响应、独立检测错误及不重新提交的挂载恢复。无密钥浏览器快照通过发布组合验证显式检测、响应丢失、取消、修复导航及窄屏布局，全程不发送业务模型请求。

## 考虑过的方案

- 合并就绪布尔值会掩盖现有证据实际支持的结论。
- 浏览器拥有的连接会随导航消失，并绕过宿主进程所有权。
- 响应丢失后自动重试，可能在恢复原操作前启动第二个服务。
- 使用工具桥接执行检查，会发现并暴露工具，还会启用执行连接的重连行为。
