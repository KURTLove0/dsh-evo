# Agent Note: 工作中心任务提交与交付验收

Status: implemented

[English](2026-10-20-work-center-intake-and-review.md) | 中文

## 问题

独立的智能体与工作流目录缺少集中查找等待事项、提交可验收标准，以及保存具体交付人工判断的入口。执行成功不能证明验收通过，当前工作区文件也不能代替历史验收证据。

## 决策

[工作中心服务](../../../../packages/business/work-center/README.zh.md)合并有界来源查询，执行所有者仍是权威。包含来源类型的标识防止冲突。筛选先于分页；读取失败明确返回，不形成虚假的完整空目录。浏览器展示已加载数量，以及会话等待事项只覆盖当前连接的范围。待处理运行任务和工作流确认优先，其余按已提交执行更新时间倒序排列。创建时间与执行更新时间分别标明；人工验收时间不会改写执行历史。当前连接观察到的待处理会话仅作为瞬态查询输入，不持久化可能在恢复后重新提出已失效问题的状态。

智能体所有者将结构化简报、提交配置版本、幂等请求标识和排队记录原子保存。执行前检查读取依赖，不执行任务或连接 MCP。预览与提交使用同一个提示词格式化函数。真正准入时再次检查依赖与版本。任务的持久化结束序号约束其已记录助手响应，即使后续会话继续也不混入新消息。停止先中止所持有的执行，再等待取消状态写入，避免存储缓慢时在取消后发起新的模型请求。

人工验收拥有独立的串行存储域。内容指纹标识已记录响应或工作流输出、提交标准、可选断言，以及显式要求的检查时文件证据。文件留存有界原始字节和指纹；期望文件不可用时不能验收通过。决策比较交付版本和人工修订号，再将完整证据与幂等决策标识原子保存。文件变化不改写已存验收证据。本地操作者标签不代表团队身份。

保存修改意见不会执行任务。创建修改任务需明确操作：智能体任务预览已提交意见、原输出及原／当前脱敏配置；工作流使用原发布版本和输入重新执行。原运行与验收记录保持完整。来源的原生提交标识使传输重试安全。

[产品提案](../../proposed/feature/2026-10-20-outcome-oriented-workbench-product.zh.md)保留更完整路线。本实现负责首批高优先级任务提交与验收机制；后续调度、集成、成本核算及团队能力仍为提案。现有任务界面与执行所有者决策继续承担各自职责。[基于证据的诊断与完整重试](2026-10-21-evidenced-work-diagnosis.zh.md)负责失败观察与完整运行重试标识。

## 影响

浏览器管理器合并刷新，串行处理续页，丢弃过期选择／查询结果，并在草稿字段变化时使未返回的预览失效。待处理会话集合变化时使分页失效。每个来源持有不透明的运行目录代次，在运行变更提交后更新，并在宿主重启时重新生成；旧游标明确拒绝，避免遗漏移动到更新时间续页位置之前的记录。带来源类型的并列位置保证确定性合并，无需加载全部历史。只有查看草稿进入页面声明的 store；权威执行与验收状态留在不依赖 React 的管理器及宿主服务。界面通过现有侧栏与主页面插槽装配，使用共享赛博主题变量。

智能体存储使用版本 5，持久化工作流存储使用版本 3。发布前旧格式拒绝打开，不迁移。验收历史与证据有部署配置的上限；容量不足会拒绝新决策，不悄悄丢弃旧记录。证据保存在宿主存储，遵循与任务会话记录相同的本地访问假设。

## 验证

真实所有者测试覆盖无执行副作用的结构化准入、重启后请求重放、来源分页、精确等待尝试决策、已记录修改意见、文件过期版本拒绝、不可变验收证据，以及明确关联的智能体修改任务。浏览器覆盖使用脚本化无密钥提供方运行实际 Web 装配，完成任务提交、精确预览、执行、保存意见但不执行、明确提交修改任务与验收。已提交的可访问性快照固定任务提交输出；响应式检查覆盖 320px、768px 与桌面宽度。管理器测试覆盖过期读取、来源错误、分页失效、等价待处理会话集合，以及未返回预览的失效。来源测试覆盖混合待处理／更新时间排序、稳定并列、变更与重启后的代次拒绝，以及独立可读的生命周期时间戳。确定性的存储屏障验证持久化尚未完成时执行已立即中止。

## 考虑过的替代方案

- 在工作中心增加执行调度器会重复既有来源的所有权与清理职责。
- 把可变验收标记放进运行状态会混淆执行结果与人工判断。
- 只保存输出路径无法保留评审者实际检查的文件。
- 保存意见后自动重跑会让验收意外执行任务。
- 截断证据后允许验收会把不完整交付当成完整交付。
