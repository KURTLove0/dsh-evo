# Agent Note: 工作台 agent 的任务检查与草稿归属

Status: implemented

[English](2026-10-20-workbench-agent-task-inspection.md) | 中文

## 问题

向独立身份分配工作时，需要看见排队任务，并确保所选身份与未发送任务文本正确关联。用身份的当前指令检查历史执行，也可能误述实际执行时的配置。

## 决策

workbench-agent 浏览器插件在支持重新挂载的视图存储中，按稳定 agent（智能体）id 保存任务文本和工作区选择。宿主确认持久化后，提交仅清空对应身份的文本；提交失败则保留。操作期间禁用输入，避免延迟确认清空新输入的文本。应用重新加载会丢弃这些浏览器草稿。配置编辑保留打开时的定义，用于比较是否存在修改；关闭已修改的编辑器时，需要明确放弃修改，或返回同一草稿继续编辑。

目录工作负载由宿主已提交的计数派生，包含仅有排队任务的身份。状态和文本筛选作用于已有执行记录。配置展开区读取执行记录捕获的定义，包括版本和指令，不受后续编辑影响。浏览器展示捕获的模型选择；选择系统默认模型不代表已确定实际执行模型。新提交重置历史筛选条件，展示新增记录。这些视图复用现有服务，不增加持久化数据，也不改变执行策略。

目录选择打开带有能力面板和配置侧栏的独立详情页，面包屑返回保留筛选条件的目录。概览将当前工作与最近十条已结束记录分开，工作面板展示完整保留历史。近三十天统计依据本地日历日内的保留提交记录派生，不另建指标存储。缺失的测量值保持不可用，界面不虚构所有权、权限、提供方连接状态或外部运行时支持。

创建表单在章节导航下保持所有能力字段挂载，原生校验可以聚焦任意无效字段，一次保存提交完整定义。导航在表单内滚动，不引入局部保存或第二个草稿持有者。

## 考虑过的替代方案

**共用任务输入框。** 更换接收者时保留文本容易误分配任务，也无法为不同成员保留不同的工作区选择。

**历史记录展示当前配置。** 查询身份的最新配置很方便，但指令或技能在执行后变化时，会给出错误的上下文。

**在宿主持久化浏览器草稿。** 持久化草稿需要为尚未提交的文本设计存储、同步与冲突语义。当前消费者只需要在同一次应用加载期间跨页面保留内容，现有视图存储已满足这一需求。

**能力标签页分别保存。** 分别保存指令、技能和 MCP 会暴露中间配置，并增加版本冲突的复杂度。单一草稿和一次保存维持配置更新的原子性，章节导航让完整表单便于使用。

## 影响

用户无需逐一打开会话，就能按技能查找成员，检查工作负载与历史配置。草稿仅存在于已加载的应用中。历史搜索仅包含所选身份保留的执行记录；解析后的模型详情和完整执行输出仍在会话中查看。

## 验证

组件测试覆盖仅有排队任务的身份发现、排序、技能搜索、任务和工作区草稿隔离、提交失败、捕获指令与历史筛选。无需密钥的工作台浏览器场景启动正式组合，创建和复制身份，提交带有不可用技能的任务，并记录目录输出、捕获配置和筛选历史的快照。不可用技能在发起模型请求前触发失败；该场景不验证模型执行。

详情测试覆盖键盘面板导航、任务聚焦、编辑器章节导航、工作类型筛选、最近历史条数限制及测量统计。业务智能体浏览器场景检查详情页头和 MCP 面板，遍历能力，并在正式应用中验证窄屏无横向溢出。
