# Agent Note: 持久原生任务触发交接

Status: implemented

[English](2026-10-21-durable-native-trigger-admissions.md) | 中文

## 问题

会话内提醒无法拥有会话关闭后仍需保留的任务计划。主机触发也跨越两次独立持久写入：保留触发记录，以及由原生智能体或工作流接纳执行。把交接回执丢失当成执行失败，会重复创建执行，或将成功标签附加到未知结果。

## 决策

Work Triggers 服务拥有独立存储域，在同一记录中保存固定目标、规则、下一名义时刻、触发历史及通知。原生智能体和工作流服务保留执行、权限、日志及人工审批所有权。默认 Web 组合挂载提供方、Remote 消费者及可选浏览器控件。[F09 提案](../../proposed/feature/2026-10-20-outcome-oriented-workbench-product.zh.md#f09-durable-work-triggers) 负责产品范围。

交接前以串行保留操作提交触发记录和下一名义目标。每次触发保留一个原生请求 UUID。调用执行者前先持久保存未确认阶段，后续回执将原生接纳与终态观察分开。响应丢失或保存回执失败保留不确定性。显式恢复比较尝试次数，复用同一原生身份及固定请求。重启后继续已保留的待处理触发；未确认交接等待操作人员。每条规则只有一次未结束触发，阻止后续工作。

固定间隔按锚点计算合并过期时刻并保留跳过次数。指定执行结束规则观察准确的来源执行，响应任意终态。暂停停止后续交接，不取消已接纳执行，也不重置规则消耗。原生状态观察和通知确认，与控制修订及人工交付验收独立。

调用方的创建 UUID 和不可变输入哈希，可在后续控制及重启后恢复修订 1 创建回执。暂停／恢复比较修订，通知确认幂等，交接恢复比较触发尝试次数。这些有界控制不需要累积的回执日志。定义及触发记录容量限制完整值，不淘汰历史；降低容量后，不变历史不阻止暂停。每次写存储时复制操作内草稿，使后续交接阶段修改不能在持久化前改变已提交内存。

[会话内持久提醒](2026-08-05-durable-web-schedule.zh.md)及[对话内交付](../simplification/2026-08-09-conversational-schedule-delivery.zh.md)保留对话语义及不添加提醒回执的决策。本服务拥有独立原生执行和显式确认通知，不把 Schedule 提交当成交付。[固定频率提醒](../simplification/2026-08-09-bounded-fixed-rate-schedule.zh.md)保留同一对话内批处理；独立任务触发不共享模型请求。[显式时区解释](../simplification/2026-08-09-explicit-schedule-time-zone.zh.md)仍与本提供方接收的 UTC 时刻分开。这些决策各自有效，未被替代。

## 考虑过的替代方案

**扩展活跃会话的提醒所有者。** 冷会话激活与任务执行需要不同身份及持久化；对话跟进不能充当可恢复的原生任务回执。

**使用新请求 UUID 重试不确定交接。** 原任务可能已经存在。原生幂等机制可恢复其身份，而新 UUID 授权另一次执行。

**原生接纳后才提交。** 原生提交与触发持久化之间崩溃会丢失原请求身份；先保留和写入未确认阶段才能保存它。

**重放全部错过间隔或并行提交未结束触发。** 停机或慢速审批会制造执行突发。合并保留固定节奏，不为每个错过时刻虚构工作。

**将可变草稿直接存入域表。** 后续阶段修改会在持久写入前可见，提交失败时内存可能领先存储。

## 影响

主机必须运行；这不是操作系统唤醒或分布式调度服务。定义及历史受明确容量限制，不承诺原生任务内外部副作用恰好执行一次。应用内通知记录交接不确定性或有来源的终态，不调用模型。外部渠道、任意事件、日历重复、删除及历史归档不属于本提供方实现。

浏览器将命令输入与权威记录分开。固定目标准备读取原执行内容，捕获当前智能体版本或原工作流发布版本，并要求显式创建。ISO 时间输入包含偏移，避免浏览器本地夏令时歧义被静默归一化。读取代次分别隔离目录、详情及准备；连接变化将上次记录保留为过期状态。页面重新挂载保留草稿及未确认命令输入。创建重试复用同一身份，然后读取当前状态，不依赖原始版本 1 回执。控制及交接恢复在下一决定前需要权威读取；重连不会自动重发命令。历史不确定通知与已恢复触发的当前状态分开展示。

## 验证

真实 JSON 存储测试覆盖重启、固定间隔合并、暂停／恢复、来源结束、不可变请求恢复、过时控制、原生接纳后的提交失败、完整字节上限、严格持久解码、观察者异常隔离及等待卸载。默认真实 Web 组合使用 HTTP 调用、真实原生执行者、脚本外部模型响应和既有审批界面；提交前关闭浏览器，恢复丢失的原生回执而不新增执行，保留工作流审批及发布输入，结束后触发后续工作，重新加载后重建通知，并检查实际模型输入日志。已保留的结果快照固定这些组合事实。浏览器控件还验证创建和控制回执丢失恢复、同一原生交接、原工作流审批、离线时另一端修改后的状态收敛、通知已读，以及键盘、双语、明暗主题及窄屏。
