# Agent Note: 配置模块导航（运行时 / 统计 / 设置）

Status: implemented

[English](2026-10-15-ui-config-module.md) | 中文

## Problem

设置面板曾是"设置"入口背后一个扁平的 section 列表（通用、模型、运行时、智能体预设、插件），其上没有任何配置模块概念。产品要求一个配置模块，导航拆成三个功能——运行时、统计、设置——同时设置内的每个页面保持不变。运行时页还渲染为卡片堆叠：全局指标（多少个运行时、多少在线、守护进程状态）可推导却无处展示，目录已携带的行级事实（来源标签、本地命令）也被丢弃。任何地方都没有跨会话的用量聚合：会话统计条是单会话的，没有界面回答"存在多少会话、消耗了多少"。

## Decision

把现有设置 shell 升级为配置模块而不是新增并列入口：侧边栏的 `sidebar.config` 座位承载全部模块入口——一个"配置"标题压三个模块行（`runtimes`、`stats` 各占一行；设置行代表 shell 未认领的第一个分区）——而 foot 上的旧"配置"触发按钮已删除：模块行是唯一入口，侧边栏不再两次命名同一入口。工作台的运行时侧边面板（`SidebarRuntimeAction`）也随之移除——一个事实一个界面，面板就是运行时的界面——工作台只剩业务工作流模块。模块行只在对应分区在账本上时存在；点击以待处理打开请求的形式、经 apply 层持有的单槽快照 store 抵达面板，面板在生效的那次渲染中消费请求，之后的渲染不会重开在陈旧请求上。

面板一次只展示一个模块。单页模块（运行时、统计）以自己的分区标题占满整列——没有导航栏，对话框的可访问名落在视觉隐藏的标题节点上；设置模块渲染自己的分区导航栏（shell 未认领为模块的页面）在模块内切页。面板绝不列出它被打开的模块之外的分区，因此打开运行时只以运行时页作答。

侧边栏的三个分组标题（工作台、工作区区域标签、配置）共用同一节奏——14/400/20 加 tertiary 标签色，各自为 h2——让整列读作同一组分节。

模块摆位按 section id 认领，而不是新的注册选项。list 槽的 `KindOptions` 是封闭集合（id/order/label/priority），`StoredEntry.options` 在存储时精确白名单这些字段；为一个 shell 的导航结构扩展 slot 核心会把展示概念放进分发契约。id 认领也符合 shell 现有的 `navIcon` 先例（按 section id 取字形，未知 id 回落齿轮），并保持声明权自洽：注册者即便声明了自己的模块，也无法本地化模块标签。`sidebar.config` 座位本身是 ui-sidebar 契约里的 shell chrome——只有几何，没有设置状态跨越它。

运行时页保持数据管线（`llm.providers` × `llm.models` 联接、守护进程提示、推送失效）并重渲染为指标条加表格。指标条只承载行已证明的事实——运行时与在线数（行不携带目录失败即在线）以及守护进程状态。表格的列是 wire 能回答的事实：带 `declared` 来源标签的服务身份、健康度（在线或逐字失败文本）、已加载模型、路由外呼的 `localCommand`。参考设计画的列（负载、智能体、费用、CLI 版本）在此没有事实来源，不凭空造列；store 现在透传 `declared`/`localCommand` 供视图展示。

新的 `@deepseek-ai/dsh-client-ui-settings-stats` 浏览器插件注册统计页：一次 `session.list` 调用在客户端聚合——会话数与已开始对话数来自行，token 用量对每行的 `tokenUsage` 投影基线求和（与会话统计条同源的持久四桶账目）。会话列举没有推送事件，页面挂载时加载、用户手势时刷新。费用卡渲染显式的无计费源占位：主机不记录价格，用量聚合也未按模型分桶，因此不发明数字。

## Consequences

- ui-settings-general 拥有模块 chrome：`ConfigNav` 占用者（`sidebar.config`）、`sidebar.group`/`sidebar.settings` 字典键、面板请求 store，以及同时服务于面板导航栏与侧边栏模块行的共享分区账本投影；section 注册选项不变，重构不需要任何功能包配合移动。
- ui-sidebar 新增一个座位（`sidebar.config`，仅几何的 owner props），渲染在浏览区与 foot 之间；每种侧栏宽度状态都传递它已传给其他座位的同一个 `wide` 标志。`settings.trigger` 槽及其占用者已从设置契约中删除——没有死座位残留声明。
- 锚定 foot 触发按钮名称的 e2e 全部改走侧边栏模块行（九个场景文件），对话框 golden 重新录制；运行时/统计页钉住无导航栏的模块形态。
- 运行时行现在暴露 `declared` 与 `localCommand`；分区始终渲染自己的标题（侧边面板的 `showTitle` 接缝随其唯一消费者一起移除，本包与 ui-settings-stats 皆然）。
- 工作台只剩业务工作流模块；`sidebar.session.action` 仍服务于剩余占用者，而 ui-settings-runtimes 不再依赖 ui-sidebar。
- ui-settings-stats 遵循标准客户端包对（host 半边空实现、invariant 伴随件、zh/en 字典、README 对）；web-app 把它挂在 ui-settings-runtimes 旁边，覆盖门禁通过 tsconfig path/reference 注册看到它。
- 未来接入计价来源时替换费用卡的占位内容即可；会话/token 卡已经基于真实数据计算。

## Alternatives considered

- **`settings.section` 上加 `group` 注册选项** —— 拒绝：list 槽选项是 slot 核心的封闭分发词汇；模块顺序与本地化的设置标签是 shell chrome，注册者只会持有概念的一半而 shell 持有另一半。
- **模块结构放在面板导航栏内** —— 首版的解读，在产品指向侧边栏后被取代：模块行与面板导航栏的切换职责重复，而侧边栏只剩一个扁平触发器，因此标题压模块的层级属于箭头指向的地方——工作区列表与 foot 之间。
- **模块行旁边保留 foot 触发按钮** —— 产品指出重复后移除：侧边栏两次命名"配置"（foot 行加分组标题），而模块行已携带全部入口路径，foot 行不再拥有自己的路径。
- **工作台的运行时侧边面板与模块行并存** —— 产品指出第二个运行时入口后移除：同一分区套上第二层 chrome（触发器、portaled 面板、自己的焦点往返）让一个事实翻倍成两个界面，而配置模块行已经能打开面板。
- **每个模块共用一条扁平面板导航栏** —— 产品要求每个模块只展示自己的功能块后被模块裁剪形态取代：打开运行时却回答一条模型导航，是面板在替未被询问的模块发言。
- **在设置旁边新增第二个并列的配置入口** —— 拒绝：两个面板会在每个设置页上重叠；"设置沿用之前的实现"把设置组固定为配置模块的第三个功能，而不是并列界面。
- **内置价格表估算费用卡** —— 拒绝：聚合未按模型或供应商分桶，任何估算都是无法追溯的近似，而且模型价格是插件不得硬编码的部署变量。显式占位让卡片保持诚实，直到存在真实的计费来源。
- **服务端聚合的 `stats` host RPC** —— 拒绝：`session.list` 已经随每行携带 `tokenUsage` 投影基线；新 wire 面只会重述一个既有答案而不增加事实。
