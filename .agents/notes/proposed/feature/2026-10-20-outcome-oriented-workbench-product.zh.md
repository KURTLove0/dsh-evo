# Agent Note: 面向交付闭环的工作台产品规划

Status: proposed

[English](2026-10-20-outcome-oriented-workbench-product.md) | 中文

首批任务提交与验收机制由[工作中心实现决策](../../implemented/feature/2026-10-20-work-center-intake-and-review.zh.md)记录。未实施的后续能力仍保持提案状态。

模板复用由[私有工作模板决策](../../implemented/feature/2026-10-21-private-work-templates.zh.md)记录。能力检查由[能力观察决策](../../implemented/feature/2026-10-21-capability-observations.zh.md)记录。F01–F11 已有各节关联的实现决策。2026-10-22，操作者选择先完善本地流程，暂缓 F12 外部系统导入与团队协作。本轮交付不包含外部连接器；F12 仍以明确来源及实际多用户需求为前提。

## Problem

项目已经具备会话、独立智能体、持久化执行队列、可发布工作流和人工确认，但使用路径主要按技术能力组织。用户需要分别进入会话、智能体和工作流才能判断哪些工作被阻塞、哪些结果值得检查，以及下一次如何复用。执行结束也不能代表业务验收通过。

本提案以本地优先的个人开发者、AI 实践者及流程搭建者为首批用户假设，建议将工作台定位为“配置可信赖的智能协作者，将目标转为可检查、可复用的交付”。这是基于当前代码的产品判断，尚未经用户访谈或使用数据验证；不承诺市场规模、收益提升或交付日期。下文未关联实现记录的新增能力仍为提案。

## Proposal

### 用户流程与信息架构

首要用户路径为：选择工作区 → 描述目标、材料和交付标准 → 检查依赖 → 执行 → 处理必要的人类输入 → 查看产物与证据 → 验收或提出修改 → 将有效方案保存为模板。

导航建议保留现有会话和工作区，新增“工作中心”，集中展示“待我处理、执行中、已结束”。“智能体”负责协作者配置与单个身份历史；“工作流”负责可重复流程设计与执行；“成果”入口在交付清单形成后加入；运行时、插件和统计继续属于配置。等待审批与执行后验收使用不同标签和动作。

### 优先级与实施顺序

优先级按用户阻塞程度、现有实现可复用程度、数据依赖和新增运行风险判断。相对工作量是工程评估，不是工期承诺。P0 的顺序表达依赖，不代表并行开发承诺。

| 编号 | 优先级 | 功能 | 首版范围与用户价值 | 相对工作量 | 主要依赖 |
|---|---|---|---|---|---|
| F01 | P0 | 工作中心与待处理收件箱 | 聚合智能体任务、工作流执行与现有会话待处理事项，定位需要动作的记录 | 中 | 有界查询、运行引用和现有等待状态 |
| F02 | P0 | 结构化任务提交与执行前检查 | 用目标、输入、交付物和验收标准减少模糊请求，提前发现工作区/运行时/技能问题 | 中 | F01 的入口、执行能力目录 |
| F03 | P0 | 成果验收 | 对确定的交付版本记录通过或需修改，连接结果、证据和后续运行 | 中至高 | F02 的验收标准、产物引用、持久化审查记录 |
| F04 | P1 | 私有模板库 | 保存任务模板及工作流模板，从副本运行并保留来源版本；先提供代码审查、文档整理、数据文件报告样例 | 中 | F02、F03；示例必须与已安装能力匹配 |

| F06 | P1 | 结果与故障诊断 | 按实际错误区分配置缺失、拒绝、超时、模型与工具失败，保留原始证据并提供正确的重试动作 | 中 | 现有运行错误、日志和重试身份 |
| F07 | P1 | 可筛选运行统计 | 按工作区、智能体、工作流、日期展示运行量、等待、耗时与可用 token 统计 | 中 | F01 的查询；指标缺失标为未知 |

### F01：工作中心最小 PRD

**用户故事。** 同时运行多个任务的用户打开工作台，先处理需要自己回答或审查的事项，再查看执行结果，不必逐个打开智能体。

**展示。** 每行展示名称或任务摘要、来源类型、工作区、原始执行状态、等待处理类别、创建时间和最近一次已知更新时间。筛选覆盖工作区、来源、执行状态和待处理类别；排序优先展示待处理事项，其余按可确认的更新时间排序。普通聊天只聚合已存在的待处理交互，不为每条会话虚构任务记录。浏览器未连接时显式显示最后已知数据和断连状态。

**交互。** 查看详情进入原有智能体、工作流或会话；回答、审批、取消与重试仍由所属服务执行。工作流审批传入准确的运行和等待 attempt；普通审批保持一次性授权语义。已结束或已处理事项不能被陈旧页面再次执行。批量批准不属于首版。

**实现。** 新增全局只读聚合查询与对应客户端插件，复用现有 Remote、运行存储及 pendingInteraction。运行引用携带来源辨别字段与原始品牌化 ID；同字面量 ID 的不同来源不得合并。执行状态由来源读取，等待与审查作为独立维度呈现。服务应提供有界分页和稳定游标；不能循环下载每个智能体的完整历史作为列表查询，也不能另存一套可变运行状态。全局目录当前不返回所有智能体任务历史，因此此功能需要新增读取 API。

**空态与错误。** 无任务时提供新建入口；筛选为空时提供清除；某来源失败时标明该来源不可用，不显示“全部处理完毕”。详情被归档或不可读时保留可解释状态，不自动删除源记录。

### F02：结构化任务提交最小 PRD

**用户故事。** 用户知道要交付什么，但不熟悉运行时、提示词和插件的配置方式。提交前可以确认任务会使用哪个工作区和执行者，以及如何判断结果合格。

**字段。** 必填目标、工作区和执行者；可选背景材料、期望文件路径/格式、验收标准与限制。首版验收标准接受清晰的文本条目，不声称能自动执行任意自然语言断言。敏感值使用凭证引用，不写入提示词、模板或导出配置。未提交草稿保留策略须在界面说明；不能沿用现有应用内草稿而宣称跨刷新保存。

**执行前检查。** 检查所选工作区与执行者仍存在、身份未归档、运行时可用、模型路由匹配及所选技能可发现。目录可用只说明配置就绪；MCP 实际连通性需带检查时间的独立探测，用户未触发时显示“未检测”。不通过发送真实业务指令来探测连接。检查通过也不替代执行时对并发变化的再次校验。

**提交与数据。** 展示最终任务内容后调用原有执行入口；用户看见的目标、约束和验收内容必须进入真实模型输入并记入会话。增加版本化任务简报，绑定到新建运行；提交使用幂等请求 ID，拒绝时保留草稿，重试传输不得创建重复运行。简报与运行关联在同一可恢复提交过程中持久化；如需跨存储写入，必须定义失败恢复而不是只依赖浏览器状态。

### F03：成果验收最小 PRD

**用户故事。** 用户希望快速判断交付是否满足要求，能指出具体问题并重新交给智能体，而不用阅读完整技术日志。

**验收页。** 同屏展示提交时的目标与标准、执行摘要、可验证产物、已运行检查及其结果、仍需人工判断的条目。摘要允许模型生成但应标明来源；“检查通过”仅来自对应检查记录。工作流自动断言结果、执行状态和人工验收分别展示。

**决策。** 已结束且存在交付版本的任务可以“验收通过”或“要求修改”；要求修改必须填写原因。评审引用确切运行、交付版本和简报版本，保存时间与本地操作者上下文，不伪造多用户身份。与执行分离的评审状态使用待验收、通过、需修改；已通过版本不会因后续重试悄然替换。并发评审使用版本检查，网络重试复用决策 ID。

**修改与副作用。** 选择要求修改只保存评审；“创建修改任务”是单独的明确操作，新建关联运行并保留原始交付，首版使用当前执行者配置且在提交前展示差异。成功文件修改的位置可以产生候选产物；终端创建、外部链接和模型声称的结果必须通过显式登记与可验证的存在性/版本信息进入交付清单。只读预览失败要显示“不可访问”，不能把当前文件内容冒充历史版本。首版不自动发送成果、合并代码、发布或部署。

### F05：能力健康检查最小 PRD

**范围。** 选择工作区与已保存执行者，检查任务准入、所选技能和已配置 MCP。另行汇总已注册模型／运行时目录，以及其声明的凭证引用或已存授权记录。缺少归属信息或依赖 CLI 环境认证时，明确标为未验证。远端目录可达不代表支持远程执行。

**检查。** 用户触发配置读取，返回观察时间和逐来源失败，不创建会话、不发送模型请求。凭证使用 describe，只读取配置存在性，不返回值。页面区分已配置、缺失、失败与未验证，并提供现有智能体、运行时、模型及设置入口作为修复路径。来源或执行者变化使已有观察过期；断连保留带时间戳的最后已知结果。

**MCP 探测。** 显式探测单个已保存服务时检查执行者版本与工作区，完成初始化和 ping 后关闭临时连接。不注册或调用工具。用户未触发时保持未检测。探测耗时、观察时间、取消／超时及清理结果分别记录。部署可配置截止时间与并发上限；卸载取消并等待探测结束。清理失败后拒绝进一步探测，直到宿主重新加载。浏览器丢失响应后不自动重试探测。

**验证。** 宿主测试覆盖依赖缺失、不含秘密值的结果、独立来源失败、过期版本、取消／超时和探测清理。无密钥浏览器使用真实装配，区分未探测与真实连接成功／失败，验证修复导航、重连和窄屏布局。

### F06：结果与失败诊断

由[基于证据的诊断与显式完整重试](../../implemented/feature/2026-10-21-evidenced-work-diagnosis.zh.md)实现。

**范围与证据。** 工作中心针对一个带来源类型的执行提供显式诊断读取，保留原始执行错误，并将观察到的失败关联到会话事件或工作流节点。稳定错误码及持久化结束原因用于区分配置缺失、拒绝、超时、模型／工具失败、取消、中断及输出限制。错误措辞本身不决定分类。即使执行最终成功，工具失败仍作为观察展示；日志缺失或不可访问保持明确，当前配置缺失不被当作历史原因。

**读取与展示。** 诊断按需读取并带观察时间，完整报告字节、条目和来源数均有配置上限。单个投影超限使对应来源不可用；汇总条目或完整报告超限会拒绝读取，不静默截断证据。选择、来源变化及重新连接会使报告过期；断连或过期时保留最后已知结果。页面显示原始证据、错误码、节点及会话引用、不可用来源，并打开适当的现有配置或会话入口。诊断不调用模型、不探测 MCP、不修改配置，也不自动重试工作。

**重试。** 重试是单独明确提交的完整新执行，提交前提示副作用风险并展示原配置与当前配置。智能体重试检查当前执行者版本并保留调用方请求标识；包括自由文本任务在内，相同请求在响应丢失和宿主重启后返回同一执行，冲突标识拒绝。工作流通过幂等完整重试操作保留原始不可变发布版本、输入、反馈和执行路由。失败验收用例在新批次中保留验证模式、用例与断言。不原地恢复失败节点。浏览器挂载或重连不会自动重发结果未确认的重试。

**验证。** 宿主用例覆盖精确错误码分类、未知措辞、已恢复的工具失败、执行结束序号范围、缺失／超限来源、来源类型隔离及完整容量限制。重试所有者用例覆盖过期配置、相同／冲突标识、并发命令、重启及响应丢失。无密钥发布组合浏览器场景覆盖失败证据、执行成功但观察到工具失败、显式完整重试、来源关联、丢失响应、过期报告、修复入口及窄屏布局。原始日志与人工交付验收保持独立。

### F07：可筛选运行统计

由[执行范围统计](../../implemented/feature/2026-10-21-execution-cohort-statistics.zh.md)实现。

**范围。** 统计按提交日期、工作区、执行来源及带来源类型的成员或工作流选择。本地日期输入解析为包含开始午夜、不包含结束日期下一日午夜，并显式携带 IANA 时区。所有者在代次校验分页前筛选。完整有界范围生成一致的总计及执行者／工作区／日期分组；排除、可用和不可用来源保持区分。容量错误要求缩小筛选，不静默使用部分分母。

**指标。** 排队、活动和已结束数量构成范围；等待属于活动的一部分，不把普通会话虚构为运行。执行成功与验证断言、人工验收保持分离，工作类型明确展示。总耗时包含排队和人工等待，排队样本止于首次已记录开始。时长带样本数，时间戳缺失或不一致保持未知。

**用量与新鲜度。** 数量统计不检查日志。显式有界用量读取在智能体所属结束序号和已知工作流直接子会话区间上复用规范计量，展示覆盖、来源缺失、区间未知及未检查运行。提供方报告可能缺少部分请求与嵌套委派，不代表金额总计。来源、筛选、待处理及连接变化只使保留观察过期，不自动读取日志。应用内跨页面挂载保留查看控件，旧结果保留原已提交筛选。全机会话用量保留独立全时段口径。

**验证。** 来源所有者、聚合、管理器及组件覆盖筛选、完整分页、标识区分、时长语义、IANA 日期、容量错误、区间归属及证据缺失。无密钥实际装配浏览器流程执行普通任务、配置生成、验收验证和人工等待，核对真实运行及用量数量，操作筛选，并检查中文与窄屏布局。

### F08：项目产物与归档恢复

归档恢复记录于[归档会话恢复决策](../../implemented/feature/2026-10-21-archived-session-recovery.zh.md)，项目目录记录于[显式项目产物决策](../../implemented/feature/2026-10-21-explicit-project-artifacts.zh.md)。

**产物范围。** 项目目录索引显式登记的文件快照，保留来源执行、工作空间、捕获时间、摘要及不可变版本。从已接受的评审登记时使用其保留的字节及准确的评审／交付版本；手动登记终端生成的文件时捕获当前字节，明确执行来源与人工验收分别成立。文件缺失、工作空间不可用、捕获超限或路径位于所选工作空间之外均拒绝登记。文本预览保持惰性；二进制只标识内容，不执行 HTML、脚本或文档。当前文件可用性由显式读取给出观察时间，不能证明历史内容。登记检查修订并幂等；响应丢失后恢复原回执，不另建版本。

**归档恢复。** 独立归档页通过现有会话及工作空间基线列出注册表级归档集合。按标题／标识及工作空间筛选元数据，只渲染有界前缀并提示缩小筛选；未知会话元数据明确显示。恢复仅移除归档成员资格，保留会话日志、工作空间记账及手动顺序，不执行任务或自动打开会话。对已恢复的已知会话重复操作不写入；缺失日志保持不可用。页面显示断线或基线读取失败，工作空间基线和会话元数据就绪前禁用恢复。Host 提交响应或归档变化帧更新所有已连接视图；重连重读权威成员集合。

**验证。** 注册表及传输测试证明恢复持久化、幂等、失败传播和记账不变。运行时测试覆盖响应／帧竞态及重连。组件及真实组合浏览器场景归档多条会话、筛选并恢复，检查第二个已连接页面，验证重启后原顺序保留，并覆盖中文、键盘焦点、明暗主题及窄屏。产物登记测试验证字节及版本准确、缺失及越界路径、乐观版本检查、重启和回执丢失后的幂等回执、纯文本预览及持久来源。浏览器场景通过终端生成文件，并在删除后保留已验收字节。

### F09：持久工作触发与应用内通知

默认 Web 提供方、原生交接协议及浏览器界面记录于[持久原生任务触发交接](../../implemented/feature/2026-10-21-durable-native-trigger-admissions.zh.md)。

**范围与部署。** 主机持有的触发器可在浏览器或会话关闭后保留，并在主机重启后恢复。执行提交和状态观察需要主机运行；这不是操作系统唤醒服务。首批规则包括未来 UTC 时刻、锚点对齐的固定间隔，以及明确选择的某次智能体或工作流执行结束。结束规则响应任何终态，不暗示执行成功。任意事件订阅、Webhook、操作系统自启动及外部通知渠道需要独立提供方，继续延后。

**目标与授权。** 每个不可变触发器指定工作空间，以及结构化任务与执行者修订号，或不可变工作流发布版本与输入。创建检查已有就绪信息，不执行模型或探测 MCP。启用明确授权后续按固定目标提交执行。原生执行服务在实际提交时重新验证，保留通常的权限和审批机制。修改规则或目标需创建独立触发器；暂停保留历史，不取消已接纳的工作。

**触发记录与重启。** 调用执行者前，在一次持久写入中保留触发记录、原生请求身份和下一次名义时刻。交接前先持久保存未确认阶段。主机丢失回执时，原生幂等提交恢复同一执行。未确认交接阻止后续触发，直至显式恢复；恢复保留同一目标及请求身份。不得把接纳报告为执行成功。分别记录所属执行及带时间的终态观察。来源元数据缺失时保持不可用，不改写上次已知结果。

**间隔与并发。** 每个规则最多存在一次未结束触发。错过的间隔合并为最近一个锚点对齐的到期时刻，记录跳过次数，推进到首个未来时刻，不突发补跑。暂停保留名义时刻，恢复可能立即到期。一次性和指定执行结束规则在保留首次触发记录后即被消耗，暂停再恢复不重置。提供方重新读取墙上时钟，使用部署配置的轮询及间隔上限，卸载时停止新提交，并在关闭存储前等待已接纳的管理或交接操作。

**持久化与上限。** 调用方提供触发器身份，使创建可在较新的控制操作及重启后恢复；不同定义复用身份会拒绝。暂停／恢复比较控制修订，旧操作不能覆盖新决定。显式交接恢复比较触发尝试次数。通知确认幂等。同一记录保存固定定义、触发历史及通知，避免保留、推进和通知部分提交。限制触发器数量、完整定义字节、触发记录数量、完整触发记录字节及完整响应；容量不足停止新提交，不淘汰证据。暂停工作不依赖持续增长的管理回执日志。

**界面。** 增加独立触发器页面及工作中心所选执行的可选贡献。展示固定目标、来源发布版本或执行者修订、解释时区与 UTC 目标、下一次名义触发、暂停状态、进行中或未确认的交接、跳过间隔、原始执行链接、失败结果及可确认的保留应用内通知。说明接纳与执行成功独立，以及主机必须持续运行。读取失败和断线保留上次结果。页面重新挂载保留未确认的创建／控制输入，重连不自动重提不确定的用户命令。使用现有赛博主题变量、可见焦点、双语、明暗主题及窄屏堆叠布局。

**验证。** 服务测试覆盖重启、到期边界、时钟跳变、暂停／恢复、错过间隔、指定来源结束、原生幂等交接、回执丢失、并发命令、容量、来源失败、提交后观察者异常隔离及卸载。无密钥真实组合场景创建智能体和工作流执行，保留审批行为，关闭再打开浏览器，并展示通知及不重复创建原生执行的恢复。浏览器及运行时测试覆盖过时读取、保留不确定输入、键盘、中文、明暗主题及 320/375/414/768px 布局。

### F10：已认证的原生远程工作

已认证传输、显式启用的原生接收端、远程执行页面及默认空机器列表的调用组合记录于[已认证原生远程接纳](../../implemented/feature/2026-10-21-authenticated-native-remote-admissions.zh.md)。页面跨重挂载保留固定权限身份与未确认输入，读取原生审批上下文，控制操作均需显式确认。

**用户流程。** 选择显式配置的机器，检查授权的远端工作空间路径及执行者／发布版本，再提交固定任务。机器目录可达不授权执行。模型凭据、工具、文件操作、权限及日志保留在远端原生服务。首版传输派发完整智能体任务及正式工作流发布版本，不把本地进程句柄移植到远程环境。

**身份与权限。** 独立版本化机器端点要求调用主机解析凭据引用，并固定远端主机 UUID 及主体。接收端解析自己的 Bearer 引用，在实际接纳或控制操作中检查显式工作空间／执行者授权。凭据不进入浏览器属性、任务内容、URL、持久请求或结果。非回环流量使用 TLS；回环接收端可通过安全 SSH 隧道，或仅转发机器端点的 TLS 代理暴露。普通浏览器信任检查与机器认证分开。远程提交不隐含工作流决策或停止权限，这些操作需要主体显式授权。

**持久化与恢复。** 远端主体与调用方 UUID 标识一次提交。交接前在同一持久记录保存固定目标及原生请求身份；响应丢失保留不确定性，不断言失败。相同内容重复创建返回保留记录，冲突内容拒绝。恢复需显式发起并比较已记录尝试次数，复用同一原生请求。原生执行所有者保留既有幂等、审批及会话日志。重连和进程重启不自动重复未确认命令。修改前即检查主机身份及主体，不能仅核对响应。

**观察与控制。** 只读取该主体当前仍获授权的保留提交。显式查询状态及已记录文本交付，分别标记来源不可用与观察时间。接纳、执行成功及人工验收相互独立。取消不删除原执行。工作流决定指定原执行及精确等待尝试；控制回执丢失后必须重新读取权威状态。远端保留普通智能体工具审批及原生评审行为。

**文件及上限。** 远端工作空间是明确命名的远程目录，不是可在本地打开或上传的路径。首版不隐含本地凭据传递、目录同步、任意远程文件浏览或自动产物下载。已记录文本输出可以跨认证协议返回；文件字节保留远端，由原生界面拥有访问。限制完整请求、保留记录、历史数量、响应及网络时间；超限显式失败，不淘汰证据。发送 Bearer 前拒绝重定向，以及带凭据或 URL 后缀的源地址。

**呈现。** 独立页面显示配置的机器身份及凭据存在性、授权工作空间路径、执行选择、固定内容、提交不确定性、原远程执行／会话、状态、输出及显式控制。草稿和未确认请求身份在页面重新挂载时保留；过期读取及离线不表示任务失败。使用既有赛博令牌、双语、明暗主题、键盘焦点及窄屏布局。只允许选择已配置的执行端点；仅提供目录的机器保持明确区分。

**验证。** 在隔离主机间通过真实 HTTP、原生智能体／工作流所有者及脚本外部模型响应验证。错误令牌、主机、主体、已撤销范围、未授权控制、重定向、请求／响应上限及凭据轮换不能绕过执行检查。响应丢失、并发相同提交、重启及显式恢复均只接纳同一次原生执行；核对远端会话中的原模型输入，以及本地没有执行。保留工作流审批及记录输出，证明被拒操作不创建原生执行。源码／HTTP 单测不能替代实际双主机组合场景。页面及默认组合验证前，此功能保持未完成。

### F11：项目知识目录

Provider、日志化模型工具、来源管理页面与默认 Web 组合见[显式项目知识](../../implemented/feature/2026-10-21-explicit-project-knowledge.zh.md)。

**范围与流程。** 首批来源是显式选择的项目内 UTF-8 文本、Markdown 和代码文件。用户选择工作空间和单个相对文件路径，启用知识授权，显式索引，再检索已启用的资料并查看或复制精确的版本化行引用。不隐含递归扫描、URL/MCP 接入、Office 转换、向量服务或将历史会话自动建为索引。完整功能包含独立页面；仅完成 Provider 的阶段仍属未完成。

**访问权限。** 来源固定工作空间身份、登记时的工作空间路径、文件系统规范根目录与目标身份，以及用户填写的路径。文件系统 Provider 负责解析、包含关系、UTF-8 解码、二进制拒绝和当前读取权限。登记只读取元数据；新索引尝试、检索和引用读取要求来源已启用，并在原工作空间完成一次新的有界文本读取。工作空间映射改变、目标重绑定、符号链接越界、文件丢失或不可读时，排除该来源并提供明确诊断。停用在服务执行器中阻止后续全部内容读取，包含历史引用；不会擦除已写入既有会话日志的结果。这是单 Host 私有授权，并非多用户 ACL。

**版本与索引。** 每次显式成功索引保留不可变的解码文本、该文本的 SHA-256、字节数、行数、捕获时间和连续版本号。解码遵循文件系统 Provider 的 UTF-8 语义，不将文本摘要称为原始文件摘要。按 LF 分行，保留行末 LF 前的 CR。索引是有界且等待完成的操作，并非持久后台作业，也不展示虚构进度。最近完成的索引尝试与最近成功版本分别保留；重新索引失败不会覆盖成功捕获。调用方身份与修订比较使重试可恢复，不会悄悄重新索引磁盘新内容。容量不足时拒绝，不淘汰保留证据。

**检索与引用。** 最新的已启用捕获使用 SQLite FTS5 trigram 做字面子串匹配；不足三个 Unicode 字符时显式使用字面扫描。参数绑定并转义 FTS 表达式，按来源和行号稳定排序，不声称语义相关性。SQLite 是可丢弃的派生索引，不是另一份持久事实。检索返回有界命中、是否还有结果、被排除的来源、观察时间，以及每个可读当前文件是否不同于索引捕获；不会静默替换过时捕获。引用固定来源 ID、捕获版本、文本摘要和从一开始的闭区间行范围；读取时逐项校验，完整返回选中行的惰性文本。对完整请求、来源数、捕获、保留历史、检索范围和响应设限；完整结果超限时拒绝，不截断引用证据。[SQLite FTS5](https://sqlite.org/fts5.html#the_trigram_tokenizer) 说明了 trigram 子串匹配与短查询限制。

**模型输入。** 独立模型工具根据发起 Agent 的工作空间检索和读取引用，不接受模型自行指定的跨工作空间权限。普通工具调用与结果将精确资料保留在会话日志中。不将整个目录注入系统提示，不把文件内容视为可信指令，也不修改 Agent Loop 或会话格式。用户文件始终作为任务材料。页面可以复制引用供用户显式使用；打开页面不消耗模型 Token。

**界面与验证。** 延用赛博主题 Token、双语文案、明暗配色、可见键盘焦点和窄屏堆叠布局。展示启用状态、不可变版本、最近尝试、来源错误及独立的当前文件新鲜度。页面重挂载保留结果未确认的写操作；重连只刷新读取。Provider 测试覆盖停用再启用、越界或重绑定路径、丢失/不可读/二进制文件、捕获变化、摘要与范围拒绝、跨空间拒绝、中文与代码字面检索、重启、并发及重复命令、完整值限制、存储失败和卸载静止。无密钥 Loader 场景必须通过真实文件系统/存储与普通模型工具日志验证；完整页面还要求浏览器回放、惰性预览、键盘操作、明暗配色、中文及 320/375/414/768px 布局。现有交付文件登记和第三方 memory MCP 继续承担各自独立职责。

### 端到端示例与产品验证

首个验证场景采用本地文档整理：用户选择一个工作区，提交“根据指定资料生成说明文档”，列出资料范围、期望路径和两条验收标准。工作中心显示实际排队或执行状态；若任务提出问题，待处理入口打开原会话。结束后用户核对文件和资料引用，保存需修改意见，明确创建修改任务，最后验收新版本并保存可复用模板。模板在 F04 实现后参与完整复用验证；F01–F03 的首版验收终点是已记录的交付评审。

用可观察的流程验证三个假设：首次使用者能完成首份交付；已有用户能发现并处理等待事项；同一类任务能通过模板重复交付。访谈与可用性走查使用真实工作区样例，不以模拟点击或完成按钮数量代替用户完成目标。代码审查和数据报告作为后续场景，分别验证代码检查证据与结构化结果的需要。

| 执行成功率 | 每类来源各自成功的已结束运行 / 该类全部已结束运行；取消和中断单列展示 |
| 模板复用 | 从已保存模板发起的任务量、后续验收结果与独立使用次数；打开模板不算复用 |
| 消耗 | 记录有来源的 token 与耗时；缺失值不计作零，无定价或计量不完整时不显示确定费用 |

先建立基线再确定增长或质量目标，不编造提升百分比。默认本地聚合；新增外发遥测必须单独说明用途与控制。P0 完成条件是上述文档整理流程在真实组装应用中可走通并覆盖失效路径。P1 在用户能稳定提交和评审后推进复用与规模化读取。P2 每项分别验证需求、部署方式与持续运行责任，不能因为已有目录或提醒工具而直接宣称支持。

### 实现约束与独立交付单元

建议按“聚合读取与工作中心 → 简报与提交 → 交付/评审记录 → 模板复用”拆成可独立评审的变更。每个新能力按 Service Definition、Provider、Consumer 组合，沿用插件扩展点；不为页面入口修改 agent-loop。存储域、Remote 命令、客户端插件分别拥有持久化、校验与呈现职责。

交付审查与模板是新增业务数据，使用版本化存储和修订检查；运行日志继续是模型输入与执行事实来源。新模型可见输入必须可从日志重建。列表读取先定义分页与来源故障语义，再设计 UI 计数。任务中心不扩大读取权限；若出现多用户或远程聚合，先增加对应授权与执行提供方。

[任务交互面板提案](2026-08-04-task-surface.zh.md)仍负责会话内的一次性结构化互动；本提案负责跨执行的工作组织与交付验收，两者没有互相替代。[智能体任务检查记录](../../implemented/feature/2026-10-20-workbench-agent-task-inspection.zh.md)继续拥有身份内任务历史和草稿规则；全局聚合与持久化简报属于新增范围。现有工作流发布、审批、验收、会话搜索和第三方记忆机制均保留其所属记录，不另建平行实现。

### 外部产品依据

GitHub 的官方流程展示了统一任务入口、跟踪执行及对产出请求评审的组合；此处只借鉴任务到评审的产品路径，不推断本项目已有 GitHub 集成。[GitHub 文档](https://docs.github.com/en/copilot/how-tos/use-copilot-agents/cloud-agent/use-cloud-agent-on-github)

LangGraph 官方文档说明持久化中断与恢复的人类参与机制；据此，后台等待与可恢复处理应有持久化协议，不能只靠浏览器提示。[LangGraph interrupts](https://docs.langchain.com/oss/javascript/langgraph/interrupts)

## Acceptance criteria

这些标准用于验证规划；已交付范围以关联实现记录为准。

1. F01 可从同一工作区列出来自两个不同智能体的任务和工作流执行；跨来源 ID 不冲突，过滤、分页及来源失败状态正确；普通会话待处理事项可打开其原交互。
2. 一个审批已经由另一页面处理后，旧页面不能再次批准；断连时显示未确认的新鲜度，重连后与权威数据一致；源服务不可用时不宣称没有待处理事项。
3. F02 对缺失工作区、归档身份、不可用运行时、模型不匹配及缺失技能给出可执行修复提示；提交失败保留输入，重复传输只创建一个运行，最终模型输入与所见简报一致并可由日志重建。
4. F03 的执行成功、自动断言和人工评审各自独立；缺失文件、无法访问文件、只有模型自述的检查和无历史快照的当前文件不会被呈现为已验证历史交付。
5. 需修改意见绑定原始交付；只保存意见不发起新执行；明确创建修改任务后可追踪新旧运行，刷新和 Host 重启后评审记录仍在。
6. F01–F03 具备焦点可见、键盘导航、减少动态效果和明暗主题；在 320/375/414/768px 及桌面宽度下主要动作可见且无页面横向溢出。
7. 服务行为通过边界与生命周期测试验证；无密钥浏览器快照经过真实配置组装验证首版流程、失效输入与陈旧决策；涉及模型实际行为的实现另增加真实提供方测试。TypeScript/Python SDK 在相应日志或生命周期接口变化时同步更新。
8. F04–F12 在实施前各自细化 PRD 和所需提供方；未完成的功能保持明确的未提供状态，不用可点击空按钮或虚构指标代替交付。

## Risks

- 全局查询会放大完整历史下载与日志读取成本，必须使用有界读取、可解释的分页和按需详情。
- 首次引导中的“检查通过”容易被误认为长期可用；检查时间、范围和执行时再校验必须明确。
- 人工验收可记录用户意见，但无法证明外部世界的业务效果；检查证据和人工判断应分别保留。
- 重试与重新执行可能重复外部副作用；首版展示全量重跑与配置选择，不承诺任意节点断点续跑或恰好一次执行。
- 本地路径、任务背景和 MCP 配置可能含敏感材料；模板、分享和后续远程能力需要独立的来源权限与凭证引用规则。
- 目标用户与首选场景尚需访谈验证；若使用集中于基础设施开发，应优先开发者调试与扩展体验，再调整工作台投入。

## Alternatives considered

- 只继续扩充仪表盘：可以增加可见性，但不能补齐任务标准、待处理动作和成果验收。
- 先做多人协作与市场：需要身份、权限、发布审核和分发机制，当前主要用户与治理需求尚未确认。
- 将智能体运行、工作流运行与聊天统一为一个可变任务状态机：会掩盖各自生命周期，并引入新的事实来源；采用带类型引用的聚合读取及独立评审记录。
- 从失败节点自动继续：可能重复外部副作用；在副作用、幂等与检查点规则建立前，首版沿用明确的新运行。
