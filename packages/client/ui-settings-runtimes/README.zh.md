# @deepseek-ai/dsh-client-ui-settings-runtimes

[English](README.md) | 中文

运行时设置页将本地部署和已保存的远程 dsh 部署组成机器目录。搜索匹配机器名称、地址、提供方名称、命令和模型 ID；状态筛选区分目录读取成功与连接或目录失败。选择机器后显示其运行时目录、已加载模型和诊断信息。本地目录连接 `llm.providers` 与 `llm.models`；缺少本地可执行程序的活跃路由仍不进入该目录。

目录根据可用宽度调整布局：窄面板将机器列表放在运行时目录上方，紧凑的顶部操作保留无障碍名称。每个运行时默认最多显示三个模型并保留模型总数；点击**展开**显示完整列表，点击**收起**恢复预览。搜索框支持直接清除，无匹配结果时可重置筛选。本地守护进程的启动说明可在运行时目录下方展开。

**连接远程机器**通过 `llm.runtimePeers` 检查 dsh HTTP 地址，成功后保存名称和地址。在远程主机运行 `dsh web`，并使当前主机能够访问其 Web 端口，通常通过 SSH 隧道连接。地址不能包含凭据、路径、查询参数或片段。已保存但不可达的机器仍显示在目录中，并保留连接错误。**打开远程主机**打开该部署的应用，由其负责远程会话。**断开连接**需要确认，且只移除保存的连接。

**管理运行时**支持创建、编辑、启用、禁用和删除兼容 Cursor CLI（命令行界面）的可执行程序配置。每份配置记录显示名称、唯一的 `runtime-` 提供方 ID、可执行程序名称或绝对路径，以及 JSON 参数数组。主机验证命令，并拒绝由适配器管理的协议和权限参数。已启用的配置通过现有 Cursor 适配器加载；缺少可执行程序的配置仍可编辑，并显示不可用状态。内置提供方仍由部署配置管理。原生 CLI 的登录和配置仍由可执行程序负责。

管理操作通过 `settings.mutate` 写入主机的 `runtime-management` 命名空间，并携带最近读取的版本号。版本冲突和验证失败在弹窗中显示，保留表单草稿；设置只读或不可用时禁用管理操作。删除操作需要确认。原生模态弹窗约束焦点并在关闭后恢复；Escape 只关闭当前管理弹窗。剪贴板写入成功后才显示复制确认。

页面打开后，本地 `settings/document-updated`、`llm/adapters-updated` 和 `connection/reset` 通知会触发刷新。远程部署在同一读取流程及**刷新**操作中更新。设置 slot 仍以顺序 15 注册在侧边栏配置分组中。

## 模型体验

视图本身不发送模型请求。保存或删除自定义配置会改变可用的提供方路由；模型选择仍由输入框负责。通过这些路由发出的请求使用 [Cursor 适配器](../../llm/llm-cursor-cli/README.zh.md)，包括其原生运行时配置和历史处理方式。

#### KV Cache 影响

查看和刷新目录没有影响。选择不同运行时会改变后续模型请求使用的提供方。

## 已知限制与延后工作

- 自定义可执行程序配置支持 Cursor CLI stream-json 协议。其他原生 CLI 协议需要接入对应的可管理适配器。
- 远程连接提供目录快照并打开远程应用，不代理远程会话或编辑远程主机配置，也不推断远程心跳或用量数据。
- 连接记录不保存凭据。请使用 SSH 隧道或已可访问的可信部署；当前主机上的配置操作仍仅限回环访问。
