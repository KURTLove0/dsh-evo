# @deepseek-ai/dsh-work-triggers

[English](README.md) | 中文

主机持有的时间及执行结束触发器，提供原生幂等交接及保留的应用内通知。`workTriggers` 与 `workTriggerGateway` 需要存储、智能体、工作流工作台、工作中心元数据及工作空间服务。默认 Web 组合挂载提供方及[浏览器控件](../../client/ui-work-triggers/README.zh.md)。[F09 提案](../../../.agents/notes/proposed/feature/2026-10-20-outcome-oriented-workbench-product.zh.md#f09-durable-work-triggers) 负责完整产品范围。

准备操作只读取原执行内容，不接纳执行。智能体目标使用当前已保存身份版本，拒绝设计执行及缺失或归档的智能体；工作流目标使用原正式执行的发布版本及输入，拒绝验收验证执行。完整准备响应受容量限制，创建时重新检查就绪状态。

## 定义与控制

固定定义指定工作空间，以及带执行者修订的结构化任务，或不可变工作流发布版本及输入。创建检查当前就绪信息，不执行模型或探测 MCP。原生服务在实际接纳时重新验证，保留已有权限及人工审批。执行者修订固定已保存的身份字段；外部提供方配置及工作流执行路由仍由所属服务在接纳时解析。触发记录不复制凭证。

规则接受未来 UTC 毫秒时间戳、以 `firstAt` 为锚点的固定间隔，或指定一次来源执行结束。结束包括所有终态，不暗示来源成功。已结束来源在首次工作器读取时即符合条件。修改定义需创建新触发器。调用方提供 UUID 作为创建身份；相同规范化输入在较新控制操作或重启后仍返回原始修订 1 回执，不同输入复用身份会拒绝。

暂停／恢复比较 `expectedRevision`，只增加控制修订。过时控制拒绝并要求读取权威状态；控制回执丢失不能证明失败。暂停保留名义时刻和历史，停止后续交接，继续观察已接纳的原生执行，不取消这些执行。通知确认只记录首次读取时间，重复操作不写入。

## 触发记录与恢复

同一记录原子保留固定定义、下一名义目标、触发历史及通知。调用执行者前先保留触发记录及原生请求 UUID。交接前持久保存未确认阶段。已接受回执记录带来源类型的执行身份及接纳时间，不证明执行成功。带时间的来源读取独立保留终态。来源查询失败时保留原观察并标记不可用；观察时间不是来源结束时间。

未确认交接阻止后续触发，并生成一条保留通知。显式恢复比较 `expectedAttempt`，复用原原生请求及目标。待处理时重复恢复控制合并；旧尝试不能授权再次重试。原生幂等机制可在回执丢失后恢复已提交执行，包括触发器保存已接纳阶段失败的情况。保留的待处理触发可在重启后继续；未确认触发等待显式恢复。恢复成功后，通知仍保留曾观察到的不确定性。结束记录增加带准确终态的通知。

每个触发器只有一次未结束触发。过期间隔选择最近一个锚点对齐的到期时刻，记录跳过次数，直接推进至首个未来目标，不突发补跑。暂停保留名义时刻，因此恢复可能立即到期。一次性及指定执行结束规则在首次保留后即消耗。目录的规则消耗及暂停状态，与最近触发的交接和执行状态独立。

工作器重新读取墙上时钟，用同一串行队列处理控制、保留及来源观察。卸载停止新交接、取消定时器，并在关闭存储前等待已接纳工作。提交后观察者失败不使已提交数据失效。提供方属于单所有者本地进程，不承诺分布式或任意外部副作用恰好执行一次。

## 上限与查询时效

配置均为正整数：`pollIntervalMs`（1000，受 Node 定时器范围限制）、`minIntervalMs`（新间隔定义为 300000）、`maxTriggers`（100）、`maxDefinitionBytes`（每个完整新定义 262144）、`maxOccurrences`（每个触发器 100）、`maxOccurrenceBytes`（每个完整新增或变化的触发记录 16384，包含私有请求身份及通知），以及 `maxResponseBytes`（每个完整响应 1048576）。响应上限不足以表示选项或固定大小控制回执时，启动拒绝。降低定义或触发容量，不阻止保持现有内容不变的暂停。容量错误保留历史，停止受影响的新交接，不淘汰记录。

查询先按明确文本、工作空间及启用条件筛选，再检查完整响应上限。目录行不含任务正文、工作流输入及完整历史。读取返回独立的保留数据，不返回创建哈希或原生提交身份。元数据读取不轮询原生服务。各规则的工作器错误明确标为当前进程观察，不是持久执行结果；重复失败不阻止其他规则推进。通知不推断模型消息。

## Model Experience

间接通过 [dsh-workbench-agent](../workbench-agent/README.zh.md#model-experience) 及 [dsh-business-workflow-local](../business-workflow-local/README.zh.md)，由既有路径记录明确授权的任务内容及原生工作流输入。

#### KV Cache effect

登记、控制和观察不产生模型请求。到期接纳创建独立原生会话，所属执行者决定日志中的提示词及请求前缀。

## Known Limitations and Deferred Work

- 主机必须运行才能提交或观察工作。不提供操作系统唤醒、多进程租约、任意事件订阅、日历重复、Webhook、外部通知、编辑、删除或历史归档。历史有容量上限，需要调整部署或创建独立触发器，不自动删除证据。未确认原生交接必须显式恢复；不承诺任务内外部副作用恰好执行一次。当前进程工作器错误重启后清空，条件持续时会重新观察。
